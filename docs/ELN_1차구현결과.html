3제출 후 잠금 · ErrataELN 제출 후에도 섹션 추가와 Errata(정정) 가능상신하면 노트 전체가 읽기 전용(편집·삭제·섹션 추가 차단), 반려·회수 시 해제. 상신 후·승인 후에도 Errata(사유 필수) 추가 가능구현 완료리뷰에서 키보드·드래그·이미지 드롭으로 잠금을 우회하는 경로가 발견돼 보강. Errata는 승인 후에도 허용(원문 불변, 정정만 추가). 원문의 "제출 후 섹션 추가"는 부분 승인을 전제로 한 것이라, 부분 승인 제거(2026-10-20)와 함께 제외. 제출 뒤 보완은 Errata로.

5공동 편집자공동 편집자 추가, 공동 편집 노트에서 수정한 사람 이름 표시, 편집자별 변경 추적헤더 Share 버튼(공유 아이콘 + 인원 수 배지)의 Share & Access 창에서 Co-editor 추가(공유와 한 곳에서 관리). 섹션별 Last edited by 표시, 변경은 Audit Trail로 추적. 승인된 노트에는 Co-editor 추가 불가구현 완료동시 편집은 다루지 않음. 원문에 동시 편집 요구가 없고, Co-editor는 번갈아 편집하는 개념. 섹션 잠금은 섹션별 저장을 전제해 노트 단위 저장과 맞지 않아 제외(사용자 결정). 공동편집자와 서명자는 다른 사람으로 구성. 헤더 아바타 대신 Share 버튼 하나(개인정보 사유로 사진·아바타 미사용).
6공유규정 준수 하에 노트·섹션을 다른 사용자와 공유 (예: R&D ↔ Process Technology 스케일업 협업)Share & Access 창(공동 편집자와 같은 창). 접근 인원 표에서 Function(배지)·Scope 확인, 행에 마우스를 올리면 Edit·Remove 표시(Remove는 확인 창 후 회수). Add People(또는 Edit)을 누르면 같은 창의 표 위에 입력 폼이 펼쳐져 대상·Function(Co-editor/Viewer)·범위·정보보호 확인 입력(모달을 겹쳐 띄우지 않음). Viewer만 섹션 단위 공유 가능. 정보보호 확인은 Audit Trail에 함께 기록구현 완료공동 편집자와 공유를 한 모달로 통합: 공유 권한 Edit과 Co-editor가 같은 개념이라 하나로 정리(사용자 결정). Function은 Co-editor/Viewer 두 단계(코멘트 기능이 없어 Commenter 제외). 정보보호 확인 체크는 원문 "under compliance"의 해석(운영에 없는 요소)이며, 감사 근거가 남도록 Audit 기록에 포함(사용자 결정). Co-editor는 항상 전체 노트, 섹션 공유는 Viewer만(원문 "sections" 공유 = 보여 주는 범위). 승인된 노트도 Viewer 공유 허용. 공유는 프로젝트 연결과 무관. 입력 폼은 현업 요청으로 중첩 모달 대신 표 위에 펼침(2026-10-16). 공유 사유(Reason) 입력칸은 제거(2026-10-16): 원문은 "규정 준수 하에"만 요구하고, 사유는 자체 해석으로 넣은 칸이었으며 화면 어디에도 쓰이지 않음.

그 밖의 개선

  • Data Visualization 표의 행·열 삭제 (헤더 셀에 마우스를 올리면 × 표시)
  • 섹션 삭제 버튼을 눈에 띄게 강조
  • 헤더 버튼 정리, 링크 스타일 통일
  • Change History의 제목과 필터를 한 줄로 배치
  • Formulation 배합 선택 → Link Formulations: 하는 일(노트에 배합 연결, 2개 이상이면 비교 표시)에 맞게 이름 변경. 기본 범위는 이 노트에 연결된 프로젝트(Related Items의 Project 항목) 전체, All projects로 넓혀 검색 가능. 표에 배합 이름·Project # 표시 (운영 Formulator 데이터에 프로젝트 번호가 있다는 전제)
  • Sticky note에 작성자·시각 표시. 볼 수 있는 사람 = 그 섹션을 볼 수 있는 사람(Share & Access 범위 그대로, 메모별 별도 공유 없음). 메모는 섹션 밖으로 나가지 않음
  • Sticky note 크기 조절(2026-10-19): 메모 오른쪽 아래 손잡이를 끌어 너비 160~480px, 본문 높이 46~360px 안에서 조절, 섹션 밖으로는 커지지 않음. 접힘 · 잠금 · 승인 · 번역 보기에서는 손잡이 숨김. 이동과 같이 Audit 기록 없음. 운영에서는 위치(x, y)와 함께 크기(w, h)도 저장
  • 노트 상태 표기를 결재 상태 하나로 통일: 리스트·노트 헤더 모두 In Progress → In Approval → Approved (기존 리스트의 Success / Failed / On Hold, Done / In Review / Draft 표기 폐기)
  • 날짜 표시를 MAPIS 표준 MM-DD-YYYY로 통일(운영 형식 MM-dd-yyyy). Experiment Date는 표준 날짜 선택기 사용(전에는 PC 언어에 따라 형식이 달라짐)

  • Related Items 추가 줄을 MAPIS 표준 입력으로 통일: Material · Project · Lab Note는 같은 입력칸 + 공통 자동완성, URL은 일반 입력칸
  • Related Items 항목을 첨부와 같은 MAPIS 표준 칩으로 가로 배치(2026-10-20): 유형 순서(Project → Material → Lab Note → URL)로 정렬, 삭제 ×는 칩 오른쪽(마우스를 올리면 진하게). 유형 이름 Note → Lab Note. "Linking a project does not grant access" 안내 문구는 팝업·리스트에서 제거
  • Audit Trail 표는 최대 높이 300px, 넘치면 표 안에서 스크롤(머리글 고정)
  • Share & Access 표를 MAPIS 표준 형식으로: Function 배지(Owner 채움 · Co-editor 파란 테두리 · Viewer 회색 테두리), 행에 마우스를 올릴 때만 Edit · Remove 아이콘 표시, Remove는 확인 창(Confirm / Cancel) 후 회수
  • 리스트: 선택된 행에 마우스를 올려도 아래로 밀리지 않음(2px 이동 제거), New Notebook 버튼은 일반 버튼 형식
