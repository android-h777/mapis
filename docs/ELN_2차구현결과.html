3. 운영 구현 시 고려 서버 · 데이터베이스

  • 노트 기본 정보: 제목, 생성일(최초 저장 시각, 서버가 기록), Primary Business · Segment(운영 DEXIF Business · Segment 코드), Site(운영 lib_site 코드). Other Business(es)는 노트-Business 연결 테이블(여러 개)
  • Related Items: 노트-연결 항목 테이블(유형 Project · Material · Lab Note · URL, 코드 또는 URL). 프로젝트 검색은 운영 TechLib 프로젝트 검색 API 재사용
  • 결재: 운영 공통 결재 모듈(결재선 · 상신 · 회수 · 결정)을 노트 단위로 그대로 사용. 섹션별 결재를 위한 서버 로직은 필요 없음(1차 계획에서 빠짐)
  • 필수 검사: 화면은 운영 공통 검사(data-required · data-required-appronly)를 쓰고, 서버도 저장 · 상신 때 같은 항목을 다시 검사
  • 첨부: 운영 공통 첨부(File 버튼 · 칩 · 끌어다 놓기) + ELN 의 버전 기록(같은 이름 → 새 버전)
  • Audit Trail: 기록은 노트 저장 · 결재 · 공유 시 서버가 남기고, 조회 화면은 관리자 메뉴에 새로 만듦
